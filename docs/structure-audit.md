# Structure audit: what the sibling Crafting Apps do, and what NoteCraft adopts

> **Last reviewed:** 2026-10-14 · **Last updated:** 2026-10-14 · **Change:** major (first version) · **Siblings audited at:** `main` of each repository on 2026-10-14

NoteCraft is the 14th Crafting App. Before writing any code we read the sibling repositories and
copied their structure and tooling, so a contributor who knows one Craft app knows this one. This
page records what exists in the siblings, what it does, whether NoteCraft adopts it, and every
place where the NoteCraft brief and the siblings disagree (the siblings win on structure and
tooling; the brief wins on feature scope and the 1:1 parity mandate).

## How the audit was done

- None of the siblings was checked out on the development machine. They were cloned read-only
  from `https://github.com/storytold/<repo>` into `.siblings/` (git-ignored, never committed):
  `photocraft`, `wordcraft`, `gridcraft`, `deckcraft`, `pdfcraft`, `figcraft`, `craft-libs`,
  `craft-launcher`, `craft-common-actions` (and, for a first pass, `cadcraft` and `soundcraft`).
- Read in full: `photocraft/AGENTS.md`, `photocraft/docs/contributing.md`, `wordcraft/AGENTS.md`
  and `CLAUDE.md`, `craft-libs/AGENTS.md`, `craft-launcher/AGENTS.md` (first half), the root
  manifests and configuration of PhotoCraft, WordCraft and GridCraft, WordCraft's `xtask`
  (`main.rs`, `layers.rs`, `parity.rs`), WordCraft's and GridCraft's engine façades, and the
  shared release workflow in `craft-common-actions`.
- **`craftrules` is not public** (`github.com/storytold/craftrules` answers 404). Its standards are
  referenced from every sibling (`standards/never-crash.md`, `progress-docs.md`, `fonts.md`,
  `icon-design.md`, `contributors.md`, `release/playbook.md`). NoteCraft follows them as the
  siblings quote them; anything we could only infer is marked *inferred* below.
- `log/devlog.md` does not exist in any sibling checkout: every sibling git-ignores `/log` (see
  Conflicts).

## Docker

| Repo | Docker use |
|---|---|
| PhotoCraft | `Dockerfile` + `.dockerignore`: a *community-maintained* self-hosting recipe for the web build (trunk → nginx). CI and releases do **not** use it; the official web build is a workflow job |
| WordCraft, GridCraft, DeckCraft, PdfCraft, FigCraft, CADCraft, SoundCraft, craft-libs, craft-launcher | none |

**Decision: NoteCraft does not use Docker** for builds, CI, tests or releases, because no sibling
does. If self-hosting the web build becomes a goal, PhotoCraft's recipe (same base images,
`rust:<ver>-slim-bookworm` builder, `nginx:1.28-alpine` runtime) is the one to copy.

### What the shared release workflow expects from an app repository

`cargo xtask version set <v>`, `packaging/macos/{import-cert.sh,package.sh}`,
`packaging/windows/package.ps1`, `packaging/linux/{package.sh,flatpak-bundle.sh}`,
`packaging/linux/ai.storyteller.<app>.desktop`, `packaging/freebsd/package.sh`,
`packaging/web/package.sh`, and release assets named `<app>-<version>-<os>-<arch>.<ext>` with a
`SHA256SUMS.txt`. NoteCraft provides `cargo xtask version`, the Linux and web scripts now, and
the rest before the first release.

### craft-launcher

The launcher's catalogue is a hard-coded table in `craft-launcher/crates/core/src/catalog.rs`
(`app(id, name, tagline, group, [three RGB colours], "storytold/<repo>")`); it downloads only
from `github.com/storytold/<app>/releases` and verifies `SHA256SUMS.txt`. NoteCraft becomes
installable through it once (1) it publishes releases with the asset names above and (2) a
maintainer adds its row to the launcher catalogue (and its icon to `assets/app-icons/`). That is
a change in another repository, so it is **not** made from here; the proposed row is:

```rust
app("notecraft", "NoteCraft", "Notebooks, notes and ink", AppGroup::New,
    [[0x8a, 0x4f, 0xc8], [0x5e, 0x2f, 0x96], [0xb9, 0x8c, 0xf0]], "storytold/notecraft"),
```

## Conventions found in more than one sibling (and adopted)

- **Everything is a command** with id, label, ribbon location/menu path, portable shortcut
  (`Mod+B`, `Mod+Shift+>`), params doc string, `mutates`, `enabled` predicate returning a
  disabled reason, and `run`. The UI, CLI, control channel and MCP all dispatch by id.
  NoteCraft's `CommandSpec` adds the parity-catalog id (brief §5).
- **Measured parity catalog**: WordCraft keeps it in `engine/src/catalog.rs` as
  `Tab|Group|Feature|command id`; `cargo xtask parity` regenerates `docs/parity-checklist.md` and
  a test enforces a floor that only rises. NoteCraft keeps the catalog in
  `docs/parity-catalog.md` (brief §0) and the engine embeds that file, so the floor test and the
  xtask read the same source.
- **Hostile-params test** (`hostile_params_never_panic` / `panic_hunt`): every command runs with
  junk parameters and must return `Err`, never panic. Adopted as `panic_hunt`.
- **Last-resort guard**: `Session::run` catches an escaped panic, restores the document and
  reports an error (`panic = "unwind"` kept).
- **Undo by snapshots**: GridCraft keeps `Arc<Workbook>` snapshots per history entry; one command
  = one entry. NoteCraft does the same with `Arc` page snapshots.
- **Headless screenshots** with `egui_kittest` (wgpu) instead of driving a desktop window.
- **Interface strings** wrapped in `tl!(…)` with per-language catalogues in `ui-egui/src/i18n/`.
- **Keytips** (ribbon access keys, Alt/F10) with a table checked by `cargo xtask keytips`
  (GridCraft) — planned for M4 with the rest of keyboard navigation.
- **Theme tokens** (`theme::Tokens`) instead of hard-coded colours.
- **Atomic saves, crash recovery** via `craft-atomic`.

## Layering: the brief vs the siblings

PhotoCraft (the reference sibling) uses exactly the brief's layers: L0 foundation, L1 `doc`, L2
algorithms/text, L3 render/gpu/format, L4 io/plugins, L5 `engine`, L6 `ui-egui` + `automation`.
WordCraft and GridCraft compress the middle (engine at L4, MCP at L5). NoteCraft follows
PhotoCraft and the brief. The CLI is an app (`apps/notecraft-cli`, exempt from layering) as in
every sibling, not an L6 crate.
